# TG_Tickets

Telegram-бот (aiogram 3) для работы с заявками и мониторинга ServiceDesk
`sd.example.ru` (SimpleOne): присылает уведомления о новых заявках по фильтру.

## Что умеет

- **SD-мониторинг** — раз в `SD_CHECK_INTERVAL` секунд забирает заявки по фильтру
  и присылает в Telegram те, которых ещё не видел.
- **Заявки по рабочему коду.** Если в теме заявки лежит код вида `SUTSPROD-17353334`,"
  он показывается первым (в уведомлении и в `/sd_last`), а `REQ`-номер — рядом:
  `SUTSPROD-17353334 (REQ4308671)`. Без кода в теме показывается `REQ`.
- **Команды:** `/help`, `/id`, `/my`, `/all`, `/sd_status`, `/sd_test`, `/sd_last N`,
  `/sd_count`, `/sd_pause`, `/sd_resume`.
- **Первый запуск без спама** — на пустом состоянии запоминает текущие заявки
  и присылает одну сводку вместо всей истории (`SD_SEED_ON_FIRST_RUN`).
- **Диалог с ИИ (необязательно)** — если задан `LLM_API_KEY`, обычный текст
  обрабатывается моделью с инструментами: можно создать заявку, найти её по
  слову или ID, посмотреть свои заявки, добавить комментарий. Без ключа бот
  работает как монитор, а на текст отвечает подсказкой по командам.

## Устройство

| Файл | Роль |
|---|---|
| `bot.py` | точка входа: Dispatcher, команды, опрос Telegram |
| `config.py` | чтение `.env` в `Config` |

| `sd_state.py` | состояние (`data/sd_state.json`): что уже отправлено |

| `tickets.py`, `tools.py` | локальное хранилище заявок и инструменты |
| `telegram_net.py` | прокси и прибитый IP Bot API (для сетей с блокировкой) |
| `health.py` | мини-HTTP `/health` для площадок, которым нужен живой порт |
| `preflight.py` | проверка готовности окружения перед деплоем |
| `access.py` | контроль доступа по `ALLOWED_USER_IDS` |

| `runtime_events.py` | отметка о жизни, обнаружение падения, очередь недоставленных |
| `sd_settings.py` | проверка обязательных настроек SD перед запуском |
| `watchdog.ps1` | локальный сторож: перезапуск бота при падении, лог, ротация |

## Доступ

Бот отвечает только пользователям из `ALLOWED_USER_IDS` (middleware в `access.py`).
Посторонний получает вежливый отказ; исключение — `/id`, чтобы человек мог узнать
свой ID и попросить доступ. Пустой `ALLOWED_USER_IDS` означает «бот открыт»: при
запуске в лог пишется предупреждение.

## Запуск локально (Windows)

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env    # заполнить значения
.venv\Scripts\python bot.py
```

Сторож (перезапуск при падении, лог в `logs/bot.log`): двойной клик по
`start_bot_watchdog.cmd`, остановка — `stop_bot.cmd`.

## Отчёты о падении и восстановлении

Процесс, который упал, сам написать не может. Поэтому бот оставляет «отметку
о жизни» (`data/runtime.json`, обновляется каждые 20 с), а при следующем старте
видит, что отметка устарела, и присылает отчёт:

```
⚠️ Бот прерывался
🔴 Не работал с: 01.11.2026 10:40
🟢 Восстановлен: 01.11.2026 10:41
⏱ Простой: 38 с
```

- Штатная остановка (`stop_bot.cmd`, Ctrl+C, SIGTERM) падением не считается.
- Если в момент падения не было связи с Telegram, сообщение ждёт в очереди
  (`data/pending_events.json`) и уходит, как только сеть вернулась — с пометкой
  «отправлено с задержкой».
- От спама защищает кулдаун: не чаще одного сообщения о падении за
  `OUTAGE_COOLDOWN_SECONDS` (по умолчанию 10 минут) — иначе падения в цикле
  превратились бы в поток сообщений.
- `OUTAGE_MIN_SECONDS` (10 с) — простой короче этого падением не считается.

Важно: отчёт формируется при следующем **запуске** бота. Если процесс умер и
никто его не поднял, сообщения не будет — для этого нужен внешний монитор на
`/health` (см. `DEPLOY.md`).
## Обслуживание файлов состояния

Файлы в `data/` (`sd_state.json`, `runtime.json`, `pending_events.json`)
принадлежат боту: он держит их в памяти и перезаписывает целиком. **Перед ручной
правкой остановите бота** (`stop_bot.cmd`), иначе его следующая запись затрёт
ваши изменения. Это же правило касается скриптов, которые меняют состояние.

## Деплой

См. [DEPLOY.md](DEPLOY.md). Коротко: `render.yaml` для Render (free web service),
`Dockerfile` — для VPS/Amvera/HF Spaces.

Ключевое ограничение бесплатных площадок: процесс засыпает или диск не сохраняется,
поэтому нужен внешний пинг на `/health` и `SD_SEED_ON_FIRST_RUN=true`.

## Безопасность

`.env` и `data/` не попадают в репозиторий и в Docker-образ (`.gitignore`,
`.dockerignore`). Логин и пароль ServiceDesk хранятся только в переменных
окружения площадки.
